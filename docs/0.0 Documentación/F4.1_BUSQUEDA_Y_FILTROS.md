## 1. Contexto y Defecto Abordado

ChatGPT realizó la auditoría contractual previa e identificó el defecto de peticiones duplicadas:

### Defecto Original:
Cuando un usuario ingresaba un texto de búsqueda (programando un timer de debounce de 300 ms) e inmediatamente cambiaba el filtro de Estado antes de la expiración de dicho timer:
1. `alCambiarFiltroEstado()` ejecutaba inmediatamente una llamada HTTP con `buscar` (texto actual) y `estado` (nuevo estado).
2. Transcurridos los 300 ms del timer original, la callback de `setTimeout` se ejecutaba provocando una segunda llamada HTTP idéntica.

---

## 2. Solución Implementada

En `frontend/rl-app/src/app/features/admin/matrices-riesgos/pages/matrices-riesgos/matrices-riesgos.component.ts`:

1. **Método Reutilizable de Cancelación**:
   ```typescript
   private cancelarDebounceBuscarPendiente(): void {
     if (this.timerDebounceBuscar) {
       clearTimeout(this.timerDebounceBuscar);
       this.timerDebounceBuscar = null;
     }
   }
   ```

2. **Ubicaciones de Aplicación**:
   - `ngOnDestroy()`: Cancela timers pendientes para evitar memory leaks o peticiones tras la destrucción del componente.
   - `alCambiarFiltroBuscar(valor)`: Cancela el timer previo, establece el valor en el signal `filtroBuscar`, resetea `pagina` a 1, y programa un nuevo timer de 300 ms que restablece `timerDebounceBuscar = null` al vencer antes de ejecutar `cargarEvaluaciones()`.
   - `alCambiarFiltroEstado(valor)`: Cancela el timer de búsqueda pendiente ANTES de invocar `cargarEvaluaciones()`. Utiliza el valor actual de `filtroBuscar` para emitir una única llamada combinada.
   - `limpiarFiltrosEvaluaciones()`: Cancela el timer de búsqueda pendiente, limpia ambos signals (`filtroBuscar` y `filtroEstado`), resetea `pagina` a 1, y ejecuta `cargarEvaluaciones()` produciendo una única llamada limpia.
